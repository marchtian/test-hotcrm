> 分支 `claude/compassionate-tesla-6q5zsn` · 总卡 #1 · 对照文档：[假设清单](./ASSUMPTIONS.md) · [取值清单](./VALUE-LISTS.md)

## 0. 环境准备（演示前一天做一次，演示当天再做一次）

```bash
pnpm install
pnpm demo:reset            # 清空本地库 + 重新 build（种子数据在首次启动时装入）
pnpm dev                   # 终端 1：http://localhost:4001 ，看到 "Press Ctrl+C to stop" 即可
pnpm demo:staff:project    # 终端 2：建演示账号、绑岗位 / 权限集、认领种子记录、填审批人
```

`demo:staff:project` 最后一行必须是 `✅ pm@objectos.ai / demo1234 — … masked.`，否则第三幕不成立。

**账号**

| 角色 | 登录 | 看到什么 |
|---|---|---|
| 数科负责人（你） | `admin@objectos.ai` / `admin123` | 一切；持有全部审批岗位，待办进「待我审批」 |
| 项目经理 王小明 | `pm@objectos.ai` / `demo1234` | 项目、工时、费用；**看不到合同额、毛利率、费率** |

**入口**：`http://localhost:4001/_console` → 应用「数科经营平台」→ 左上「区域」切换 **CRM / 项管平台**。
Studio（流程图）：右上工具图标 → 自动化。

**演示前 30 秒检查**
1. 项管平台 → 成本执行 → 成本监控：三行，成本状态分别为 正常 / 预警 / **已超支**（韩城 MES，成本管控 = 超支锁定工时）
2. 审批中心 → 全部：新库正常会有 **4 条商机立项审批 + 1 条工时审批**（种子写入触发的）。留着给第 5 步的「一屏混排」用；第 2 步用的商机「集团销售管理 CRM 系统」若显示「审批中已锁定」，先在这里按 `a` 通过它
3. 两个浏览器（或一个普通 + 一个隐身）：一个登录 admin，一个登录 pm

## 1. 主线（约 25 分钟）

### 第 0 步 · 开场：拿着 Excel 点导航（2 分钟）
- 打开客户的流程表，指着「系统路径」列。
- 区域「CRM」：客户管理 · 线索管理 · 商机管理 · 审批中心 —— 和表里一字不差。
- 切到区域「项管平台」：售前立项 · 交付立项 · 成本计划 · 成本执行 · 工时填写 · 项目报表 · 审批中心。
- 台词：「这两个区域就是你们表里的 CRM 和项管平台，菜单名照抄的。下面我按表的顺序点。」
- **念一遍[假设清单](./ASSUMPTIONS.md)**，请对方随时打断。

### 第 1 步 · 步骤 1 备注的规则（1 分钟）
- CRM → 客户管理 → 客户 → 打开「景德镇建设工程招标代理有限公司」（客户分类 = 招标代理公司）。
- 商机管理 → 商机 → 新建：客户选这家 → 保存 → **被拒绝**，提示「仅可用于付款回款，不能发起商机」。
- 台词：「这条是你们表里步骤 1 的备注。备注里的规则我们也做成了系统规则。」

### 第 2 步 · 第一幕：商机 → 一键售前立项（3 分钟）
- 商机 → 打开「集团销售管理 CRM 系统」（90 万，提案阶段）。指一下「立项信息」「铁三角」两个分组：是否投标、级别、签约主体、业务分类、项目名称、收入确认类型。
- 点头部按钮 **「生成售前立项」**。
- 切到项管平台 → 售前立项 → 售前项目：新记录「集团销售管理 CRM 系统一期」——项目名、客户、业务分类、金额、铁三角全部带过来了。
- 台词：「表里步骤 15 写的是『必须引用 CRM 商机』。我们做成一键带出，**同一批数据不再录第二遍**。」
- 若商机显示「审批中已锁定」：先去审批中心通过（这就是步骤 11 的商机立项审批），再点按钮。

### 第 3 步 · 售前立项审批 → 转交付立项（4 分钟）
- 打开售前项目「邯郸黑猫安全生产监控平台」（草稿）。填四类成本测算和报价 → **Bizcase 总成本、毛利率自动算出**。
- 「项目角色」里项目总监 = Dev Admin（脚本已填）。把状态改为「已提交」保存。
- 记录页出现「审批中已锁定」。审批中心 → 待我审批：第一条「Presales Project Approval · Project Director Review」——审批人来自记录上的**项目总监字段**。按 `a` 通过 → 出现第二级「PMO Director Sign-off」→ 再通过 → 售前状态「已立项」。
- 台词：「审批人可以来自岗位、也可以来自记录上的字段。你们表里的五级链，就是在这张图上加节点。」→ 打开 Studio → 自动化 → `presales_project_approval` 看流程图。
- 打开售前项目「唐山黑猫数据中台」（已立项）→ 点 **「转交付立项」** → 交付项目生成：四类测算变成了四类预算、**预算基线**自动算、报价变成合同额；售前状态变「已转交付」。
- 台词：「步骤 27 的『以 Bizcase 总成本作为考核基线』——基线在这里产生，以后不会被改写。」

### 第 4 步 · 第二幕：超支拦截 → 追加预算 → 审批 → 放行（5 分钟）
- 项管平台 → 成本执行 → 成本监控：指着「韩城黑猫 MES」：预算 520,000 / 实际 539,600 / **103.8% · 已超支** / 成本管控 = 超支锁定工时。
- 工时填写 → 全部工时 → 新建：项目 = 韩城 MES，月份 2026-10，工时 100，级别 高级，状态 **已提交** → 保存 → **被拒绝**：「已超预算，工时填报已锁定… 请先提交预算追加申请」。
- 成本计划 → 预算追加申请 → 打开 BA-0001（草稿，已写好调整原因与差异分析）→ 状态改「已提交」→ 保存。
- 审批中心 → 待我审批：「Budget Adjustment Approval · Finance Manager Review」→ `a` 通过。
- 回到韩城项目：已批准追加 120,000 → 预算总额 640,000 → 成本状态 **预警**（84%）。
- 再建同样的工时 → **成功**。
- 台词：「系统管住了成本，但不是一刀切：成本管理员把这个项目设成『锁定』它才拦；追加走审批，批了自动放行。这就是步骤 36 和 32。」

### 第 5 步 · 流程专场（3 分钟）
- 审批中心 → 全部：一屏混排 工时 / 售前 / 预算 / 商机 几种待办；演示 `j` `k` 移动、`a` 通过、`r` 拒绝。
- 挑一条 **`r` 拒绝** → 记录状态退回 → 修改后重新提交。
- 系统设置 → 审批 → **审批委派（外出）**：出差时代理。
- Studio → 自动化：左侧列出全部审批流；点 `timesheet_approval`：审批人 = 记录上的「审批人」字段（由项目经理自动填）。

### 第 6 步 · 第三幕：换个人看同一个项目（2 分钟）
- 第二个浏览器，`pm@objectos.ai` 登录 → 项管平台 → 交付项目 → 韩城 MES。
- 并排对比：管理员能看到「合同与毛利」分组（合同额 700,000 / 毛利率）；**项目经理这一组根本不存在**，工时列表里也没有费率列。
- 台词：「这是权限集上的字段级控制，列表、详情、导出、API 一律生效，不是页面上藏了一下。」

### 第 7 步 · 项目报表（2 分钟）
- 项管平台 → 首页（项目经营看板）：4 个 KPI；**「基线 · 调整后 · 实际」三柱图**——韩城那组：灰 52 万、蓝 64 万、绿 56 万。
- 下面两张表：**按实施成本中心** vs **按核算成本中心**——同一笔钱两个口径。顶部筛选「实施成本中心」可以切。
- 台词：「实施和核算分开，是因为干活的部门和背成本的部门经常不是一个。」

### 第 8 步 · 收尾（1 分钟）
- 切回区域「CRM」：「数科自己用的是项管平台；推给子公司的时候，用的是这个 CRM——客户、商机、报价、合同、产品都是现成的。同一个平台。」
- 拿出[取值清单](./VALUE-LISTS.md)：「这些下拉框都是配置。今天能填的，我们现场填。」

## 2. 常见翻车点

| 现象 | 原因 / 处理 |
|---|---|
| 看板图表空白一两秒 | 图表懒加载，等 1–2 秒；不要刷新 |
| 「待我审批」为空但「全部」里有 | 该审批路由到的岗位没有持有人（脚本已让 admin 持有全部岗位；重跑 `pnpm demo:staff:project`） |
| 记录页顶部出现「越权通过 / 拒绝 / 转签 / 撤回」 | 管理员兜底按钮，任何审批都能用；演示时尽量用审批中心 |
| 通过后弹红色错误 `RESUME_FAILED` | 记录没有 owner → 通知节点无收件人；重跑 `pnpm demo:staff:project`（会认领无主记录） |
| 登录 pm 报「必须修改密码」 | 重跑 `pnpm demo:staff:project`（会复位密码并清掉首登改密标记） |
| 改了 `src/` 后页面没变 | `pnpm dev` 会自动 rebuild + restart；但**换数据库**需要 `pnpm demo:reset` + 重新 `pnpm dev` |
| 演示数据被玩坏了 | Ctrl+C → `pnpm demo:reset` → `pnpm dev` → `pnpm demo:staff:project`，3 分钟恢复 |
| 想要「五级审批」现场演示 | Studio 里该 app 是只读（打包应用）；说明「克隆后即可编辑」，不要现场改 |

## 3. 这版明确不做的（客户问到怎么答）

见 [backlog #8](https://github.com/marchtian/test-hotcrm/issues/8)。一句话版本：
- 成本按月分解、人工按级别 × 工时 × 人数分解 → 下一版
- 月度 TS 网格填报 → 下一版
- 五级审批 → 平台已支持，等贵司审批矩阵
- 开票 / 收款 / 采购合同 / 订单 → 在 ERP，做集成视图
- 投标模块 → 留了「是否投标」字段，范围待确认
